# 아이폰·아이패드 파일 앱 썸네일

iNAS 의 파일 제공 확장(File Provider)이 NAS 의 사진·동영상 썸네일을 직접 만들어 파일 앱에 넘겨주는 방식과, 2.2 를 만들며 겪은 실패와 해결 방법을 정리한다.

## 동작 방식

파일 앱이 목록을 그리다 썸네일이 필요하면 확장의 `fetchThumbnails` 를 부른다. 확장은 아래 순서로 JPEG 를 만들어 돌려준다. 파일 앱은 받은 그림을 자체 캐시에 보관한다.

1. **iNAS 썸네일 캐시**: App Group `Library/Caches/Thumbnails/<서버>/<해시>.jpg`. 해시 키는 경로·크기·수정 시각·픽셀 크기라서, 파일이 바뀌면 새로 만든다. iNAS 앱의 "캐시 지우기" 로 비운다.
2. **시놀로지 썸네일**: 같은 폴더의 `@eaDir/<파일 이름>/SYNOFILE_THUMB_XL.jpg` 등이 있으면 받아서 줄인다. NAS 에서 미디어 색인을 켠 폴더에만 있다.
3. **사진**: 30MB 이하이면 받아서 ImageIO 로 줄인다.
4. **동영상**
   - **mp4·m4v·mov·3gp**: AVFoundation 이 맡는다. 사용자 정의 URL(`inas-smb://`)과 리소스 로더(`SMBAssetLoader`)로 연다. AVFoundation 이 "이 위치를 읽어 줘" 하면 그 범위만 SMB 로 256KB 씩 읽어서 넘긴다. 파일을 받아 두지 않는다.
   - **mkv·avi·wmv·flv·ts 등**: FFmpeg 가 맡는다(`VideoFrame.swift`). 사용자 입출력 콜백으로 FFmpeg 가 읽자는 위치만 SMB 로 512KB 씩 읽어 넘긴다.
   - **장면 고르기**: 영상의 10% 지점(최대 2분) 근처 키프레임을 쓴다. 거의 검은 화면이면 1분씩 뒤로 두 번 더 찾는다. 관람등급 화면이나 검은 화면을 피하려는 것이다.
5. 결과를 긴 변 512px JPEG 로 캐시에 저장한 뒤 파일 앱에 준다.

FFmpeg 는 ffmpeg.org 공식 소스(8.0)에서 디코더·디먹서·swscale 만 켜서 빌드한다. 라이선스는 LGPL, 네트워크와 GPL 구성 요소는 넣지 않는다(`Scripts/build-ffmpeg-ios.sh`, 결과물 `Vendor/FFmpeg.xcframework` 는 git 에서 뺀다).

## 실패와 해결

### 1. 파일 앱이 기다리다 그만두면 썸네일을 만들지 않았다

- **증상**: 폴더를 여러 번 들락날락해야 썸네일이 하나씩 나왔다.
- **원인**: 썸네일을 차례로 만들었다. 파일 앱이 요청을 취소하면(폴더를 나가거나 오래 걸리면) 남은 것을 만들지 않았다.
- **해결**: `ThumbnailJobs` 가 썸네일 만들기를 한곳에서 맡는다. 파일 앱이 취소해도 만들던 것은 끝까지 만들어 캐시에 넣는다. 그래서 다음에 볼 때는 바로 나온다. 같은 파일은 한 번만 만든다.

### 2. 멈춘 작업이 차례를 막았다

- **증상**: 어떤 영상에서 1분 넘게 답이 없었고, 그 뒤 썸네일도 나오지 않았다.
- **해결**: 단계마다 시간 제한을 걸었다(`withTimeout`).

  | 단계 | 제한 시간 |
  |---|---|
  | mp4 영상 정보(moov) 위치 확인 | 15초 |
  | AVFoundation | 40초 |
  | FFmpeg | 90초 |
  | FFmpeg 의 SMB 읽기 한 번 | 20초 |

  시간을 넘기면 포기하고 다음 썸네일로 넘어간다. 시간 초과는 다음에 다시 시도한다.

### 3. 확장 메모리 한도 약 20MB (핵심 원인)

- **증상**:
  - 시뮬레이터에서는 다 나오는데 아이폰에서는 일부 mp4 가 끝내 나오지 않았다.
  - 확장 프로세스가 기록 없이 사라졌고, 충돌 보고서도 없었다.
- **조사 방법**:
  - 확장이 App Group 파일에 단계별 기록을 남기게 했다.
  - 기록 줄마다 `phys_footprint` 와 `os_proc_available_memory()` 를 함께 적었다.
  - Mac 에서 `xcrun devicectl device copy from --domain-type appGroupDataContainer --domain-identifier group.com.moimz.iNAS --source Library/Caches/...` 로 기록을 가져와 봤다. 아이폰 시스템 로그는 `sudo` 없이 Mac 에서 볼 수 없어서 이 방법을 썼다. 조사가 끝난 뒤 이 기록 코드는 뺐다.
- **알아낸 것**:
  - 파일 제공 확장의 메모리 한도는 **약 20MB** 다(iPhone 17, iOS 27). 시뮬레이터에는 한도가 없어서 재현되지 않는다.
  - 영상 정보가 3~7MB 인 2시간짜리 mp4 를 FFmpeg 로 풀면, 샘플 표를 메모리에 올리는 순간 15~16MB 를 넘는다. 이어서 "메모리 경고(심각)" 가 뜨고 iOS 가 확장을 끝낸다.
  - mp4 앞부분 14MB 를 한꺼번에 메모리에 받는 것도 같은 이유로 끝났다.
  - mkv 1080p 는 FFmpeg 로 가장 많이 쓸 때도 12MB 라 한도 안이었다.
- **해결**:
  - mp4 계열은 AVFoundation + 리소스 로더로 바꿨다. 영상 정보를 풀고 디코딩하는 일을 시스템이 해서, 확장은 3~4MB 만 쓴다. NAS 에서 읽는 양은 4~8MB, 걸리는 시간은 0.1초 안팎이다. 영상 정보가 파일 앞에 있든 뒤에 있든 같다.
  - mp4 를 FFmpeg 로 넘기는 것은 AVFoundation 이 못 열 때뿐이다. 그것도 영상 정보가 1MB 이하일 때만 넘긴다(`ffmpegMoovLimit`). 더 크면 확장이 끝나지 않게 바로 포기한다.
  - 썸네일은 한 번에 하나씩 만든다.
  - FFmpeg 디코더는 메모리를 덜 쓰게 설정했다: 스레드 1개, `AV_CODEC_FLAG2_FAST`, 루프 필터 생략.

### 4. 실패를 기억하지 않아 같은 실패를 되풀이했다

- **해결**:
  - 형식 문제처럼 다시 해도 같은 실패는 `.fail` 표시를 남겨 다시 시도하지 않는다. 네트워크 실패는 표시하지 않는다.
  - 만드는 동안에는 `.trying` 표시를 둔다. 확장이 도중에 끝나면 표시가 남고, 두 번 남으면 포기한다. 확장이 계속 끝나는 파일 하나가 다른 썸네일까지 막지 않게 하려는 것이다.
  - 새 빌드가 깔리면 `.fail`·`.trying` 표시를 지워 다시 시도한다. 고친 내용이 반영되게 하려는 것이다.
  - 표시는 "캐시 지우기" 로도 지워진다.

### 5. 파일 앱은 "썸네일 없음" 답도 기억한다

- 한 번 `nil` 로 답한 파일은 파일 앱이 다시 묻지 않는다. iNAS 캐시를 지워도 그대로다.
- 그래서 고친 뒤에도 예전에 실패한 파일은 썸네일이 나오지 않을 수 있다. 파일이 바뀌거나 파일 앱 캐시가 비워져야 다시 묻는다.

## 썸네일 실패 기록 (iNAS 앱)

iNAS 앱 첫 화면의 "썸네일 실패 기록" 에 최근 10개를 보여 준다(`ThumbnailFailures`, App Group UserDefaults).

- 줄마다 파일 이름, 이유, 서버, 폴더, 시간이 나온다.
- 같은 파일이 다시 실패하면 새 기록으로 바뀐다.
- "기록 지우기" 로 지운다. 서버를 지우면 그 서버의 기록도 지워진다.
- 확장이 만드는 도중에 끝난 파일(메모리 한도 등)은 다음에 확장이 뜰 때 기록된다.

| 기록에 나오는 이유 | 뜻 |
|---|---|
| 사진이 30MB 보다 큼 | 큰 사진은 받지 않는다 |
| NAS 에서 사진을 받지 못함 (다음에 다시 해 봄) | 네트워크 문제 |
| AVFoundation 실패(…), 영상 정보가 커서 FFmpeg 도 못 씀 | AVFoundation 이 못 여는 mp4 인데 영상 정보가 1MB 넘음 |
| FFmpeg: … 프레임 못 얻음 / 형식 열기 실패 / 읽기 한도 넘음 | FFmpeg 가 장면을 못 뽑음(코덱·해상도가 함께 나옴) |
| FFmpeg 가 90초 안에 못 끝냄 | 시간 초과, 다음에 다시 시도 |
| 만드는 도중 확장이 끝남 (메모리 한도 등) | 4K HEVC mkv 처럼 디코딩에 20MB 넘게 드는 경우 |
| 만들다 확장이 여러 번 끝나 포기 | 위가 두 번 되풀이됨 |

## 남은 한계

- 4K·10비트 HEVC 를 FFmpeg 로 디코딩하면 프레임 하나가 20MB 를 넘을 수 있다. 이 경우 확장이 끝나고, 두 번 뒤 포기한다. 이런 파일이 mkv 대신 mp4·mov 이면 AVFoundation 이 처리한다.
- 세로로 찍은 영상의 회전은 AVFoundation 경로만 반영한다(`appliesPreferredTrackTransform`). FFmpeg 경로는 아직 반영하지 않는다.
